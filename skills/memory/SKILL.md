# 长期记忆

每个新会话开始时，claude-boost 会把记忆索引 `MEMORY.md` 注入上下文。你负责写入和维护。

## 存在哪

- **全局**（关于用户本人、通用偏好）：`~/.gemini/claude-boost/memory/`
- **项目**（只对某个项目成立）：`<工作区>/.agents/memory/`

## 记忆文件格式

一个文件只记一件事，文件名用短横线英文，如 `prefers-pnpm.md`：

```markdown
---
name: prefers-pnpm
description: 一句话摘要，用来判断以后是否相关
type: user | feedback | project | reference
---

事实本身。
feedback / project 类型再加两行：
**原因：** 用户为什么这样要求（让以后能判断边界情况）
**如何应用：** 什么时候、怎么用
```

类型含义：`user` 用户是谁、擅长什么；`feedback` 用户对你做事方式的纠正或认可；`project` 代码和 git 里看不出来的项目背景、约束、截止日期（相对日期一律换成绝对日期）；`reference` 外部资源位置（文档、看板、工单系统）。

## 写入步骤

1. 先看对应目录下的 `MEMORY.md` 有没有已经覆盖这件事的条目——有就更新那个文件，不要重复建。
2. 写记忆文件。
3. 在同目录 `MEMORY.md` 加一行索引：`- [标题](文件名.md) — 一句话钩子`。`MEMORY.md` 只放索引，不放内容，保持简短。
4. 简短告诉用户记下了什么。

## 不要记

- 代码结构、git 历史、README / AGENTS.md 里已有的东西——直接读源头就行。
- 只对当前这次对话有用的临时信息。
- 密码、令牌、密钥等敏感信息。

发现某条记忆已经过时或错误时，直接改掉或删除（同时删索引行）。用户说"忘掉 X"时同理。
