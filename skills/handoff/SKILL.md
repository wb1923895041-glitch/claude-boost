# 会话交接

交接文件放在 `<工作区>/.agents/handoff/`，文件名 `YYYYMMDD-HHmm-<英文短名>.md`。
新会话开始时，claude-boost 会自动提示工作区里 7 天内还没被接手的交接文件。

## 写交接（旧会话）

先核实再写：用 `git status` / `git diff --stat`（或 rewind 技能的 `list`）确认实际改了哪些文件，跑一下相关测试确认当前状态。不要凭印象写"已完成"。

```markdown
---
status: open
created: 2026-11-17 15:30
---

# <任务名>

## 目标
用户最终要什么（用用户的原话 + 明确的完成标准）。

## 当前状态
- 已完成并验证：…（怎么验证的）
- 已改但未验证：…
- 未开始：…

## 关键文件
- `path/to/file.ts` — 改了什么 / 为什么重要

## 决定与原因
- 选了 A 而不是 B，因为 …（用户确认过的决定要标明"用户已确认"）

## 踩过的坑
- 试过 X，失败，原因 …（避免新会话重蹈覆辙）

## 下一步
1. 具体到可以直接执行的第一步
2. …

## 怎么验证
`<命令>` 预期看到 …
```

写完后把文件路径告诉用户，并告诉他们：开新对话说"继续上次的交接"即可。不要因为要交接就提交 git。

## 接手（新会话）

1. 读 `.agents/handoff/` 下 `status: open` 的最新文件（多个时列出来让用户选）。
2. 用 `git status` 等快速核对文件里写的状态和实际是否一致，不一致以实际为准并告诉用户。
3. 把 frontmatter 的 `status` 改为 `picked-up`，然后从"下一步"开始做。
4. 用一两句话告诉用户你接手了什么、准备先做什么。
